# Prompt Optimizer v3.0

## 简介

基于 **12 维度定量评分框架** + **14 种反模式检测** + **跨维度依赖矩阵** + **形式化操作原语** + **反事实推理** + **回归验证** 的工业级提示词优化技能。每项优化从输入验证到回归验证，形成完整的闭环——确保每处修改都有逻辑依据、可验证、可回退，禁止无依据的脑补和扭曲原意。

**v3.0 核心升级：** 从"定性分析"升级为"定量评分 + 形式化操作 + 回归验证"的完整质量闭环。

## 使用方式

### 斜杠命令

`/prompt-optimizer <理论方向> | <原始提示词>` — 优化指定方向的提示词

例如：

```text
/prompt-optimizer Python代码审查 | 检查这段代码有什么问题 def calc(a,b): return a/b
```

### 自动触发

当用户输入以下关键词时自动激活：

- "优化提示词" / "优化prompt" / "prompt优化"
- "改进提示词" / "提示词优化"
- "rewrite prompt" / "improve prompt"
- "逻辑推断优化" / "精准提示词"
- "领域优化" / "优化指令"
- "prompt engineering" / "提示词工程"

### 输入格式

用户需要提供两部分信息：
1. **理论方向（Domain）** — 该提示词的用途场景/领域（越具体越好）
2. **原始提示词（Original Prompt）** — 需要优化的提示词原文

两者可以在同一条消息中提供，也可以分步提供。如果只提供了其中一部分，技能会自动询问缺失的信息。

## Workflow 说明（7 步闭环）

| 步骤 | 名称 | 说明 |
|------|------|------|
| **Step 0** | 输入验证与预处理 | 完整性检查、结构识别、质量预检（6 项）、语言检测 |
| **Step 1** | 解析与结构化输入 | 提取理论方向 + 原始提示词，处理边界情况 |
| **Step 2** | 系统性 12 维分析 | 定量评分 (0-5)、反模式检测 (14 种)、跨维度依赖矩阵、P0/P1/P2 分级 |
| **Step 3** | 策略选择与冲突消解 | 方向性策略 (12 类) × 针对性策略 + 冲突解决协议 (5 类冲突) |
| **Step 4** | 形式化优化执行 | 操作原语 (14 种，含 PRE/POST/验证/反事实/副作用/回退)、过优化防护 |
| **Step 5** | 回归验证 | 优化后重过 12 维度、回归缺陷检测、迭代修正 (最多 3 轮)、原意保存验证 |
| **Step 6** | 输出结果 | 优化后提示词 + 推理链摘要 + 逐项优化说明 + 质量对比报告 + 使用建议 |

## 技术细节

### 新增核心机制 (v3.0)

| 机制 | 位置 | 说明 |
|------|------|------|
| **定量评分** | Step 2b | 每个维度 0-5 分，有具体评分锚点（0/3/5 分各有示例） |
| **反模式检测** | Step 2c | 14 种经过验证的提示词反模式，自动扫描命中 |
| **跨维度依赖矩阵** | Step 2d | 12×12 矩阵标记维度间的直接/间接影响关系 |
| **冲突解决协议** | Step 3c | 5 类冲突 + 形式化消解规则 + 冲突日志 |
| **操作原语** | Step 4a | 14 种操作类型，每种含 PRE/POST/验证/反事实/副作用/回退 |
| **反事实推理** | Step 4b | 每项优化附带"不执行会怎样"分析 (C0/C1/C2 强度分级) |
| **过优化防护** | Step 4d | 6 种过优化信号 + 自动降级/移除机制 |
| **回归验证** | Step 5 | 优化后重过全部 12 维度 + 迭代修正 (最多 3 轮) |
| **原意保存验证** | Step 5d | 4 项核心意图保存检查 |
| **质量对比报告** | Step 6 | 优化前后评分对比表 + 提升箭头 + 回归警告 |

### 使用的工具

无需额外的工具或权限，纯文本处理。

### 输出说明

优化结果直接以文本形式返回，包含五部分：
1. **优化后的完整提示词**（代码块格式，可直接复制使用）
2. **推理链摘要**（7 步完整推理路径）
3. **逐项优化说明**（每项改动含推理链 + 反事实强度 + P0/P1/P2 等级）
4. **质量对比报告**（优化前后 12 维度评分对比表，含提升趋势箭头）
5. **使用建议与迭代方向**（可选，含过优化警告）

## 关键原则

- **逻辑推理链**：原文引用 → 维度分析 → 策略选择 → 优化执行 → 反事实推理 → 回归验证
- **禁止脑补**：不得添加原文没有的新任务、新事实或新的指令目标
- **禁止扭曲原意**：保留核心意图，不改变指令的实质目标
- **形式化验证**：每项操作的 PRE/POST 条件必须在执行前后验证
- **过优化防护**：长度膨胀 > 3x、约束过密、CoT 误用等自动降级
- **回归闭环**：优化后重验证 → 发现问题 → 迭代修正 → 重新验证

## 注意事项

- 理论方向越具体，优化策略越精准
- 技能不会将优化结果写入任何文件，仅输出到对话中
- 12 维度框架 + 14 种反模式覆盖了提示词质量的核心方面
- 部分优化操作依赖对理论方向的合理推断，这类推断会在说明中标注
- 提示词工程是迭代过程，建议用户实际使用后再回来进行第二轮优化
- v3.0 的回归验证 (Step 5) 确保优化不会引入新问题，但有最多 3 轮迭代上限
