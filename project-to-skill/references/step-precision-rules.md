# 步骤精度参考手册

> 为 `project-to-skill` 生成高质量、高精度 Skill 的快速参考。
> 用于 Step 6e（颗粒度校准）、Step 7d（步骤分解）和 Step 10b（精度交叉验证）。

---

## 1. 动词对照表

生成 Skill Workflow 步骤时，必须使用"高信息量动词"，禁止使用"低信息量动词"：

| 类别 | 高信息量动词 ✅ | 低信息量动词 ❌ |
|------|---------------|---------------|
| 数据读取 | 读取、加载、导入、解析、拉取 | 获取、拿到 |
| 数据输出 | 写入、导出、序列化、渲染、打印 | 输出、给出 |
| 数据变换 | 转换、映射、聚合、展开、拼接、切片、排序、过滤、筛选、分组 | 处理、操作 |
| 验证检查 | 校验、验证、断言、检查、比对、确认 | 判断、看看 |
| 错误处理 | 跳过、忽略、重试、回滚、中止、降级、标记 | 处理、应对 |
| 创建生成 | 创建、构建、生成、初始化、实例化 | 做出、搞出 |
| 通信 | 发送、通知、推送、广播、回复、回调 | 联系、告诉 |

**规则**：如果找不到合适的动词 → 说明你对这个步骤的理解还不够具体，回到 Step 5a 重新阅读源代码。

## 2. 名词精度速查

| 模糊名词 ❌ | 精准替换 ✅ |
|-----------|-----------|
| 数据 | 按具体格式命名：CSV 行列表、JSON 对象、dict[str, int]、bytes 缓冲区 |
| 文件 | 按用途+格式命名：输入配置文件(.yaml)、日志输出文件(.log)、缓存文件(.cache) |
| 结果 | 按含义命名：验证报告、聚合摘要、错误列表、处理统计 |
| 参数 | 按名称+类型命名：input_path(str)、verbose(bool,默认False) |
| 配置 | 按作用域命名：数据库配置、日志配置、API 密钥配置 |
| 信息 | 按内容命名：错误信息、进度信息、版本信息 |
| 列表 | 按元素命名：User 列表、Transaction 数组、str 集合 |

## 3. 步骤颗粒度判断卡

设计 Workflow 步骤时，对每个步骤快速自测：

### 3a. 单一职责测试

| 问题 | 通过标准 |
|------|---------|
| 这个步骤做了几件事？ | 1 件事 → ✅ 通过；≥2 件事 → ❌ 拆分 |
| 这些事属于同一逻辑层次吗？ | 验证+清洗属于"预处理层"→ ✅；读取文件+发送邮件(不相关) → ❌ 拆分 |
| 步骤名称包含"和""或""与"字吗？ | 出现 → ❌ 隐含多件事，检查是否应拆分 |

### 3b. 信息密度测试

| 检查项 | 通过标准 |
|--------|---------|
| 步骤描述（五要素合计）字数 | ≥ 60 字 → ✅；< 60 字 → ❌ 过度简化 |
| 输入部分是否列出了参数名/类型/默认值 | 全部列出 → ✅；省略 → ❌ |
| 处理过程是否有明确的条件分支描述 | if/else 写出 → ✅；隐含假设 → ❌ |
| 输出部分是否有明确的类型描述 | 类型名+内容说明 → ✅；仅写"结果" → ❌ |

### 3c. 条件边界测试

| 问题 | 检查方法 |
|------|---------|
| 如果输入为空，发生了啥？ | 步骤中有处理描述 → ✅；没有 → ❌ |
| 如果输入格式不对，发生了啥？ | 有校验和错误输出 → ✅；没有 → ❌ |
| 如果处理中途失败，发生了啥？ | 有重试/回滚/中止描述 → ✅；没有 → ❌ |
| 如果输入超出范围，发生了啥？ | 有边界值处理 → ✅；没有 → ❌ |

## 4. 五要素模板速查

```markdown
### Step N: <动词性短语>

**输入**：<参数1(类型,必填/可选,默认值,取值范围)>、<参数2(类型,必填/可选)>

**处理过程**：
1. <具体操作1> — <边界条件说明>
2. <具体操作2> — <边界条件说明>
3. <特殊情况处理>

**输出**：<输出名(类型,内容说明)> → <递给哪个步骤/最终输出>

**异常处理**：
- <错误场景1> → <处理方式>
- <错误场景2> → <处理方式>

**步骤衔接**：<完成后下一步是？有否条件跳转？>
```

## 5. 精度交叉验证单

Step 10b 执行精度验证时使用此清单：

### 参数完整性核对
- [ ] 参数映射表中的每个参数是否都在 Workflow 步骤中有对应描述？
- [ ] 每个参数的默认值是否准确反映了源代码？
- [ ] 每个参数的可选值范围是否完整列出？
- [ ] 参数之间的依赖关系是否标注？

### 分支覆盖核对
- [ ] 每个 if/else 分支是否有对应的处理路径？
- [ ] 每个 match/switch case 是否有对应的处理描述？
- [ ] 每个 try/except 是否有对应的异常处理？
- [ ] 隐式 else 分支（默认路径）是否也有描述？

### 幻觉检测
- [ ] 步骤中描述的功能在源代码中确实存在？
- [ ] 步骤中列出的参数名与源代码一致？
- [ ] 步骤中列出的错误场景在源代码中有对应处理？
- [ ] 步骤中提到的数据格式与源代码中一致？

### 过程完整性核对（v2.1.0 新增）
- [ ] **循环次数精确**：循环边界（for range / while 条件）与源代码一致，未简化为"多次"
- [ ] **重试策略完整**：重试次数、延迟策略、退避公式与源代码一致，未简化为"重试"
- [ ] **错误恢复路径完整**：每次重试失败后的处理（continue/break/raise/retry）与源代码一致
- [ ] **退避公式精确**：退避算法（固定/指数/线性）的公式参数与源代码一致
- [ ] **循环后状态完整**：循环退出后的数据状态（成功/失败列表、计数器）与源代码一致

### 整体质量
- [ ] 步骤数量是否合理？（太少→过度简化，太多→碎片化）
- [ ] 是否有至少一个示例（Do/Not This）？
- [ ] 是否在 When NOT to Use 中列出了边界情况？
- [ ] generated Skill 的 frontmatter 是否完整？
- [ ] 生成的 Skill 无字数限制，所有过程细节已完整录入？
