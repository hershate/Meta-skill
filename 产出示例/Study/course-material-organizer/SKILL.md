# Course Material Organizer

## Purpose

根据用户提供的课程大纲或知识点列表，按用户所处的学习阶段（课前预习、课后复习、冲刺整理、专项攻克）和学习目标，自动生成与之匹配的结构化学习资料。不同阶段有不同的学习曲线和资料组织方式，本 Skill 通过主动向用户收集需求参数来定制最合适的材料。

## When to Use

- 用户拿到了一份课程大纲或教案目录，需要配套的预习/复习/备考资料
- 用户即将进入新课学习，需要课前预习材料（概览、前置知识、预习要点）
- 用户已经学完部分课程，需要课后复习巩固材料（重点总结、练习题、易错点）
- 用户有需要重点攻克的知识点或专题，需要集中整理和分类归纳（冲刺整理模式）
- 用户有特定薄弱环节或复杂专题，需要深度梳理和针对性练习（专项攻克模式）
- 用户说"帮我整理这门课的资料"、"根据这个大纲做预习材料"、"出一些复习题"、"期末怎么复习"
- 学生、教师、自学者需要根据不同阶段快速生成定制化课程资料

## When NOT to Use

- 用户只需要某个具体概念的单次解释 —— 应直接回答，无需生成整套材料
- 用户提供的内容已经是完整的教材或教师讲义 —— 直接使用即可，无需重新整理
- 用户没有提供任何课程信息（课程名称或大纲）且不愿意补充 —— 无法确定范围
- 用户需要的是纯操作指南（如"如何安装 XX"）—— 应直接给出步骤
- 用户只是想了解本 Skill 的功能说明 —— 应直接回答而非执行完整流程

## Workflow / Steps

### Phase 0: 需求采集与参数确认

在开始任何材料生成之前，**必须通过主动提问**收集以下信息。一次性提出多个问题（而非逐条追问）以节省交互轮次。

#### 必须确认的参数清单

**第一组 — 基础信息（必问）：**

1. **课程名称与大纲**
   - 询问："请提供课程名称和课程大纲/目录。可以是章节列表、知识点清单，或者任何形式的内容框架。"
   - 如果用户提供的是模糊主题（如"高等数学"）而没有具体大纲，追问："有没有具体的章节列表或知识点列表？即使是大致的方向也可以，我会帮你补充细节。"
   - 如果用户完全无法提供大纲，告知本 Skill 需要至少一些内容框架才能有效工作

2. **当前学习阶段**
   - 使用单选提问："你当前处于哪个学习阶段？"
   - 选项：
     - **课前预习** — 即将上课，需要提前了解核心概念和前置知识
     - **课后复习** — 已经上完课，需要巩固知识、做练习
     - **冲刺整理** — 有需要集中消化的知识点或专题，需快速分类整理
     - **专项攻克** — 有特定薄弱环节或复杂专题，需深入梳理和针对性突破
   - 根据回答切入对应的 Phase 1/2/3/4

**第二组 — 补充参数（根据第一阶段回答选择性提问）：**

3. **时间预算**
   - 询问："你打算用多长时间完成这些内容的整理和学习？每天大约能投入多少时间？"
   - 时间充裕（≥3天）：材料可更详细完整，每个知识点包含充分讲解和练习
   - 时间紧张（≤1天）：材料需精简，仅保留核心概念 + 分类 + 难点标注

4. **当前水平**
   - 询问："你对这门课目前的基础如何？（零基础 / 有部分了解 / 掌握大部分但需要梳理 / 熟练但希望深入）"
   - 零基础 → 突出背景知识、基础概念、减少高阶内容
   - 已掌握部分 → 跳过已熟悉内容，聚焦薄弱环节
   - 熟练但不熟悉应用 → 突出综合练习和知识串联

5. **具体需求/痛点**
   - 询问："有没有特定的薄弱章节、难点、或希望重点关注的领域？"
   - 收集用户特别关心的章节，在材料中倾斜更多篇幅和练习

6. **输出深度偏好（可选）**
   - 询问："你希望材料的详细程度是？（精炼要点式 / 中等详细 / 非常详尽含完整讲解）"

#### 参数记录

在收集完所有参数后，在输出目录的索引文件中记录本次配置，便于用户后续调整或生成其他阶段材料。

#### 参数验证规则

在记录配置前，对用户提供的参数进行合理性验证：

| 参数 | 验证规则 | 不合规处理 |
|------|---------|-----------|
| 课程大纲 | 至少包含 1 个章节或模块条目 | 0 个条目 → 追问要求提供至少一个章节；仅 1 个条目且过于宽泛（如"第一章"）→ 追问具体主题 |
| 时间预算 | 数值合理且在预期范围内 | 负数或 0 → 追问合理时间；描述模糊（如"很快"）→ 要求给出具体天数或小时数 |
| 当前水平 | 必须在 4 个选项中明确选择 | 未选择 → 追问明确选择；选择"零基础"但又提到"学过相关知识" → 提示矛盾并让用户重新确认 |
| 学习阶段 | 必须在 4 个选项中明确选择 | 选择了两个或以上 → 告知每次只运行一个阶段，请用户优先选择最紧急的阶段 |
| 知识点范围（冲刺/攻克模式） | 用户必须提供具体知识点或章节列表，不能为空 | 空 → 追问要求提供至少 1 个具体知识点；范围过大（如"整本书"）→ 请用户列出最需要整理的 3-5 个具体主题 |

如果参数存在矛盾（如"零基础"但"时间预算只有 1 天"），主动指出矛盾并提供建议："零基础的情况下 1 天时间完成系统整理会比较紧张，建议优先选择 2-3 个最核心的知识点进行聚焦整理。"

### Phase 1: 课前预习模式

适用场景：用户即将进入新课学习，需要在上课前对内容有整体了解。

#### Step 1: 解析课程大纲

解析用户提供的大纲或知识点列表：

- 识别章节标题和子主题结构
- 标记层级关系（父主题 → 子主题）
- 推断知识依赖关系（哪些需要先学，哪些可以并行学习）
- 识别大纲中可能的前置知识缺口（例如出现"导数"概念但大纲没有前置的"极限"章节）

**异常处理：**
- 大纲内容为空或过于模糊 → 回到 Phase 0 追问补充
- 大纲结构不清晰（如只有关键词列表） → 按合理逻辑推断知识依赖关系，并在索引中标注推断依据
- 大纲包含口语化表述 → 规范化处理为课程章节格式

#### Step 2: 定制预习材料策略

根据时间预算和用户水平，确定预习材料的深度和体量：

| 参数 | 策略 |
|------|------|
| 时间充裕（≥3天准备） | 完整预习包：概念引入、背景知识、前置回顾、预习问题清单，每节约 15-30 分钟阅读量 |
| 时间紧张（≤1天） | 快速预览版：每节仅保留核心概念一览 + 预习要点 + 课堂准备清单，每节约 5-10 分钟 |
| 零基础 | 补充必要的前置知识背景，标注课堂中"必须重点听讲"的难点 |
| 有基础 | 侧重高级预习——思考题和关联分析，帮助在课堂中参与深度讨论 |

#### Step 3: 搜索补充资料

对每个章节的核心概念，使用 WebSearch 搜索：

- **概念引入类**：通俗易懂的入门教程或科普文章（适合零基础）
- **背景知识类**：前置知识的相关资料
- **可视化资源类**：图解、动画、视频教程链接（特别是对抽象概念）
- **优秀教案类**：其他教师/机构对该章节的教案或公开课笔记

每个章节至少搜索 1-2 个概念的教学资料。

**异常处理：**
- API 搜索无结果 → 降级为使用已有知识解释，在资料中标注"无外部资料参考"
- 搜索结果与章节主题不匹配 → 跳过不强制使用
- 网络超时 → 提示用户搜索服务暂时不可用，使用内置知识继续

#### Step 4: 生成预习材料

在 `course-material-organizer/output/` 下创建目录结构：

```
output/
├── index.md                               # 会话配置索引
└── <课程名称-slug>/
    └── preview/                           # 预习阶段
        ├── overview.md                    # 课程概览
        ├── 01-<章节slug>.md              # 各章节预习材料
        ├── 02-<章节slug>.md
        └── ...
```

每个章节文件使用以下模板：

```markdown
---
chapter: "章节编号 - 章节名称"
duration: "预估预习用时"
prerequisites: ["前置知识1", "前置知识2"]
class_prep_questions:
  - "课堂上要重点关注的 1-2 个问题"
focus_points: ["预习要点1", "预习要点2"]
---

## 本节课核心概念一览

<3-5 个核心概念的极简定义，每个 1-2 句>

## 前置知识回顾

- <前置概念 1>：一句话回顾 + 与本课的关系
- <前置概念 2>：一句话回顾 + 与本课的关系

## 预习要点

### 重点理解
1. <要点 1> — 为什么重要
2. <要点 2> — 为什么重要

### 难点预警
- ⚠️ <难点 1>：容易混淆的地方，课堂需特别注意
- ⚠️ <难点 2>：如果看不懂没关系，带着问题去上课

## 带着问题去上课

以下问题可以在课堂上重点关注：
1. <问题 1>
2. <问题 2>

## 扩展阅读（可选）

- [标题](URL) — 来源，预估阅读时间
```

**异常处理：**
- 某章节只有很少的内容 → 不强行填充模板，保持简洁即可
- 某章节内容过于丰富（超过 300 行）→ 拆分为子文件（如 `01-1-子节.md`）

#### Step 5: 生成预习概览

在 `overview.md` 中生成课程整体概览和预习计划：

```markdown
# <课程名称> — 课前预习指南

## 课程信息
- **课程名称**：...
- **预习阶段总时长**：预估 XX 小时
- **推荐安排**：每天预习 XX 个章节

## 学习路线图
<章节1> → <章节2> → <章节3>
              ↓
        <章节4> → <章节5>

## 预习计划

| 章节 | 预习要点 | 预估用时 | 课堂注意 |
|------|---------|---------|---------|
| 01 | ... | 20 min | ⚠️ 难点预警 |
| 02 | ... | 15 min | |
```

#### Step 6: 输出报告

向用户报告：
- 生成了几个章节的预习材料，保存在哪个路径
- 预估总预习用时和每日建议安排
- 提醒用户"带着问题去上课"部分的内容可以在课堂中重点关注
- 询问用户是否需要切换学习阶段（如上完课后生成复习材料）

#### Step 7: 预习材料质量校验

在向用户输出报告前，对已生成的预习材料进行质量校验。逐项检查以下清单：

**① 模板合规检查：**
- [ ] 每个文件是否包含 YAML 元数据头（--- 包裹的 frontmatter）
- [ ] 元数据字段是否完整（chapter, duration, prerequisites, class_prep_questions, focus_points）
- [ ] 文件内容结构是否与预习模板匹配：核心概念一览 → 前置知识回顾 → 预习要点 → 课堂问题 → 扩展阅读
- [ ] 模板中的占位符（`<...>`）是否已被实际内容替换，无残留

**② 命名规范检查：**
- [ ] 文件名格式是否为 `NN-<章节描述>.md`（NN 为两位数字章节号）
- [ ] 描述部分不使用空格、特殊字符（仅允许中文、英文字母、数字、连字符）
- [ ] 文件编号与课程大纲中的章节编号一致

**③ 内容完整性检查：**
- [ ] 每个章节文件至少包含 3 个以上的具体概念点（非单纯框架）
- [ ] 前置知识回顾中指向了具体的先修概念（而非仅写"无"）
- [ ] 课堂准备问题有具体的指向性（能让学生带着明确目标去听课）
- [ ] overview.md 中的计划表具体可行，时间估算合理

**④ 否决项（任一不满足则必须修正）：**
- [ ] 无残留占位符（`<...>`、`...`、`[填写]`、`TODO`）
- [ ] 无空内容文件（仅有模板结构而无实质内容）
- [ ] 无文件间矛盾（相同概念在不同文件中解释一致）
- [ ] YAML 元数据完整无缺失

**校验不通过处理：**
- 否决项不通过 → **强制修正后再输出**，不修正不向用户报告
- 非否决项检查失败 → 优化内容后输出，在报告中告知用户已优化
- 同一批次超过 3 个文件不通过 → 检查整体生成策略，可能需要重新生成

修正后重新校验，直至全部通过。

### Phase 2: 课后复习模式

适用场景：用户已经上完部分或全部课程，需要系统性的复习巩固。

#### Step 1: 解析课程大纲

与预习模式 Step 1 相同。额外的输入确认：
- 课程已上到哪里（已完成哪些章节）？如果只完成了部分课程，仅对已完成章节生成复习材料
- 用户上课时的笔记或记录（如有），融合到复习材料中

#### Step 2: 定制复习材料策略

| 参数 | 策略 |
|------|------|
| 时间充裕（≥3天） | 完整复习包：每节包含知识总结、典型例题、练习题、易错点分析 |
| 时间紧张（≤1天） | 快速回顾版：每节仅保留公式/定理/关键点 + 经典例题 + 知识结构图 |
| 有薄弱章节 | 在该章节分配更多篇幅和练习题 |
| 整体掌握较好 | 侧重综合应用题和知识串联，减少基础内容 |

#### Step 3: 搜索补充资料

对每个章节搜索：
- **典型例题**：不同难度的例题和解题思路
- **常见错误**：该章节学生常犯的错误类型
- **综合应用**：跨章节的综合应用题
- **记忆技巧**：口诀、图表、思维导图等记忆辅助

#### Step 4: 生成复习材料

目录结构：

```
output/<课程名称-slug>/review/
├── overview.md                    # 复习总览
├── <章节slug>.md                  # 各章节复习材料
├── ...
└── comprehensive-exercises.md     # 综合练习（可选）
```

每个章节文件使用以下模板：

```markdown
---
chapter: "章节编号 - 章节名称"
difficulty: "基础/中等/困难"
key_concepts_count: X
practice_questions: Y
---
```

#### Step 5: 生成复习计划

在 `overview.md` 中生成复习路线图和张弛有度的复习排期：

````markdown
# <课程名称> — 课后复习指南

## 复习概况
- **复习范围**：<已完成章节>
- **预估总用时**：XX 小时
- **薄弱环节**：<标注用户提到的薄弱章节>

## 复习路线图
```
````

### Phase 3: 冲刺整理模式

适用场景：用户有特定的知识点或专题需要集中整理和分类消化。

#### Step 1: 确认整理范围

**必须先让用户提供具体需要整理的知识点或专题列表，技能不自行决定整理范围。**

- **知识点列表**—— 要求用户列出需要整理的具体知识点、章节或专题：
  - 如果用户说"帮我整理XX课程的全部内容" → 追问："请指定你最需要整理的 3-5 个具体知识点或章节，我会基于这些进行深度整理。"
  - 如果用户提供了具体列表（如"极限、导数、积分"）→ 直接使用
  - 如果用户说"帮我冲分/备考" → 追问："请列出你希望我帮你整理的具体知识点或题目类型，我会按难度分类为你整理。"

#### Step 2: 定制整理策略

根据时间预算和范围大小，确定材料的深度和体量：

**时间/深度矩阵：**

| 时间预算 | 策略 | 输出体量 |
|---------|------|---------|
| 充裕（每个知识点≥1天） | 深度整理：每个知识点配完整讲解 + 例题 + 练习题 + 易错点 | 每个知识点一个独立文件 |

- 零基础用户：概念解释使用通俗类比，减少专业术语密度
- 有基础用户：侧重知识串联和综合应用

- **教学资料**：核心概念的通俗解释和教学文章

- **记忆技巧**：帮助记忆复杂知识点的口诀或方法

- 之前设置的时间预算和当前水平
- 用户之前提到的具体需求和薄弱环节
- 已覆盖的章节列表（避免重复生成）

#### Step 2: 确定新旧材料衔接策略

根据已有阶段和当前阶段的组合，选择衔接方式：

| 已有 \\ 当前 | 预习 | 复习 | 冲刺 | 专项攻克 |
|------------|------|------|------|---------|
| **预习已生成** | — | 复用预习中的大纲解析和前置知识分析；对预习标记的"难点预警"在复习中重点覆盖；对预习中的"课堂准备问题"在复习中给出答案 | 复用预习中的大纲解析结构作为组织框架 | 复用预习中标注的概念难点作为攻克突破口 |
| **复习已生成** | 不常见，按用户具体需求处理 | — | 复用复习中的易错点分析，快速定位需冲刺的知识点 | 复用复习中的薄弱章节标记和易错题作为攻克目标输入 |
| **冲刺已生成** | 不常见 | 不常见 | — | 复用冲刺中的难度分类信息和难点标注作为深入攻克参考 |
| **专项攻克已生成** | 不常见 | 不常见 | 不常见 | — |

**关键原则：**
- **不重复生成已有的内容**：如果某个章节在之前阶段已详细覆盖，新阶段只引用链接而非再次完整生成
- **继承而非覆盖**：新阶段的材料与已有材料并存，不覆盖之前的文件
- **建立跨阶段链接**：在新材料中用 `[参见预习材料](./preview/01-xxx.md)` 指向已有材料中的相关章节
- **阶段递进标注**：在 overview 中标注"该内容已在 X 阶段覆盖过，本阶段不再重复"

## 材料质量保证框架

本框架定义了所有阶段材料必须满足的最低质量标准，是每个阶段 Step 7（材料质量校验）的上层规范。

### 质量维度定义

| 维度 | 权重 | 说明 | 达标标准 |
|------|------|------|---------|
| **模板合规** | 否决项 | 文件结构与指定的阶段模板一致 | 核心章节齐全，无缺失；模板中的占位符已全部替换 |
| **元数据完整** | 否决项 | YAML frontmatter 包含该阶段的必需字段 | 字段完整且值合理（非空字符串） |
| **内容深度** | 30% | 概念解释使用了日常语言、类比或实例 | 每个核心概念至少有一段通俗解释，非照搬教科书定义 |
| **可操作性** | 25% | 材料包含可执行的练习、问题、检查项 | 练习题有参考答案或思路提示；检查项有明确标准 |
| **一致性** | 25% | 不同文件之间内容无矛盾，引用正确 | 相同概念在不同文件中解释一致；文件间链接有效 |
| **来源标注** | 20% | 外部资料标注了来源 URL | 所有引用外部资料的位置标注了可访问的 URL |

### 否决项规则（硬性门禁）

以下任何一项不满足，材料**不得**向用户输出：

1. **残留占位符**：文件中包含 `<...>`、`...` 作为内容占位、`[待补充]`、`TODO`、`[填写]` 等未替换内容
2. **模板结构缺失**：与官方模板对比，缺少任一核心章节（如预习模板缺少"课堂准备问题"）
3. **YAML 元数据缺失**：文件头缺少该阶段模板定义的必需字段
4. **空内容文件**：文件仅有模板框架（标题 + 空节）而无实质性内容
5. **严重矛盾**：同一概念在两个文件中出现相互矛盾的解释（如一个文件说"时间复杂度 O(n)"，另一个说"O(n²)"）
6. **无声替换**：未经说明直接用内置知识替换了用户提供的明确信息

### 质量门禁流程

```
材料生成完毕
      ↓
执行 Step 7 质量校验（逐项检查清单）
      ↓
 ┌─ 存在否决项不通过？ ──→ 定位问题 → 修正 → 重新校验
 ↓ 否
 ┌─ 非否决项评分 < 60%？ ──→ 优化内容 → 重新校验
 ↓ 否
输出报告 ← 校验通过，可以交付
```

**执行规则：**
- 质量校验在材料生成后、输出报告前自动执行，不可跳过
- 否决项不通过 → 必须在本次会话中修正，不修正不输出报告
- 非否决项评分 < 60% → 建议优化后再输出；如时间紧张无法优化，在报告中说明改进空间
- 同一批次超过 3 个文件校验不通过 → 检查生成策略是否存在系统性偏差，调整后重新生成全部文件
- 修正完成后重新执行整套校验流程，直至全部通过

### 学科适应性规则

不同学科的材料质量侧重点不同，在质量校验时按学科类型调整检查重点：

| 学科类型 | 模板调整 | 质量检查侧重 |
|---------|---------|-------------|
| **理工科**（数学/物理/计算机/工程） | 保留所有模板节，增加"公式推导"和"典型计算" | 公式精确性、例题步骤完整性、计算题答案正确性 |
| **文科**（历史/文学/哲学/语言） | 保留基础模板，增加"概念辨析"和"案例分析"，减少"计算" | 概念定义准确性、案例与理论的匹配度、引用来源完整性 |
| **医学/生物** | 保留基础模板，增加"解剖/流程图"和"记忆辅助" | 术语准确性、记忆口诀的准确性、临床/实验案例的准确性 |
| **商科/法学** | 保留基础模板，增加"案例分析"和"框架模型" | 模型框架的完整性、案例分析的逻辑链、法规/条款的准确引用 |

在生成材料前，根据课程名称自动推断学科类型，选择对应的模板调整策略和质量检查重点。如果无法推断（如课程名称不明确），默认使用标准模板。

## Constraints

- Always 在开始生成任何材料之前，先通过提问收集用户的阶段、时间、水平等参数（Phase 0）
- Always 一次性提出多个选择性问题（而非逐条追问），最大限度减少交互轮次
- Always 根据用户选择的阶段（预习/复习/冲刺整理/专项攻克）使用对应的模板和策略
- Always 在 `course-material-organizer/output/` 下按阶段分类输出所有材料文件
- Always 每个材料文件头部包含 YAML 元数据块，标注阶段、章节、重要性等信息
- Always 先解析用户输入的大纲结构再拆分章节 —— 不凭空编造课程大纲
- Always 在生成材料前搜索补充资料，而非仅依赖内置知识
- Always 根据用户的时间预算调整材料体量 —— 时间紧则精简，时间充裕则详实
- Always 每个文件使用统一模板，保持格式一致
- Never 直接粘贴搜索结果原文 —— 用自己的话重新组织和解释
- Never 跳过提问步骤 —— 没有参数配置就生成的资料很可能不适合用户需求
- Never 在用户选择了一个阶段后，擅自混入其他阶段的材料模板
- 搜索到的外部资料来源在材料中标注 URL
- 专项攻克模式下，所有材料仅针对用户指定的知识点进行整理，不添加用户未指定的内容
- 当用户提供的课程信息极为有限时，使用合理推断补充，并在材料中标注"推断内容"
- 如果用户在前一次会话中已生成过某阶段的材料，再次调用时先检查输出目录是否存在同名课程，避免重复
- Always 每个生成的材料文件必须通过 Step 7 质量校验后再输出，不通过校验不向用户报告
- Always 文件命名严格遵循 `NN-<章节描述>.md` 格式：NN 为两位数字章节编号（01, 02, 03...），描述部分不使用空格和特殊字符
- Always 同一课程多次调用时，先检测 `output/` 下是否已有同名目录，自动启用 Phase 5 多阶段协同流程
- Always 跨阶段材料之间建立显式链接引用（格式：`[参见X阶段](./X阶段/文件名.md)`），而非孤立生成
- Always Step 7 质量校验发现否决项时先修正再输出，不得跳过
- Always 根据课程名称自动推断学科类型，选择对应的质量检查侧重（见"学科适应性规则"）
- Always `output/index.md` 作为全局索引，记录所有阶段的配置参数和文件链接，每次生成后更新
- Never 在材料文件中残留 `<...>`、`...`、`[待补充]`、`TODO`、`[填写]` 等任何未替换的占位符
- Never 生成仅有模板框架而无实质性内容的文件（每个文件至少 200 字实质性内容）
- Never 在未完成 Step 7 质量校验前向用户报告"生成完成"或给出完成信号
- Never 同一课程的不同阶段材料出现内容矛盾或章节编号不一致
- Never 在冲刺整理或专项攻克模式下，擅自添加用户未指定的知识点或专题
- Never 在冲刺整理或专项攻克模式下，判定或暗示某个内容"会考/不会考"、"重要/不重要"
- Never 在任何材料文件中出现"考试"、"考点"、"考分"、"得分策略"、"提分"等暗示技能具备考试判断能力的表述
- 质量校验的否决项不可绕过，所有校验结果（包含否决项列表和修正记录）记录在 `output/index.md` 中
- Always 在生成的每个材料文件中按难度（基础/中等/困难）对知识点进行分类
- Always 在每个章节材料中标注**难点**、**易混淆点**、**易忘点**三类属性，作为默认分类维度
- Never 在材料文件中出现"必考"、"常考"、"偶尔考"、"高频考点"、"重点掌握"等自动指定重要性的标签
- Never 在材料文件中出现"必得分"、"争取分"、"放弃分"等自动划分得分策略的表述
- Never 在材料文件中使用 ⭐ 或 🔴🟡🟢 等符号体系标注重要度或优先级
- Never 在材料文件中承诺或暗示"经过本材料训练可以提升 X 分"等分数提升效果
- 如果用户主动提供了"重点"、"常考"等信息，在材料中标注"用户指定：XXX"以明确区分，且不将这些信息用作结构调整的依据

## Examples

### ✅ Do This — 用户有完整课程大纲 + 明确阶段

**用户输入：**
```
/课程资料 我下学期要学《计算机网络》，大纲是：
1. 计算机网络和因特网
2. 应用层
3. 传输层
4. 网络层
5. 链路层
想做一些课前预习资料
```

**期望做法：**
1. 提问确认：距离上课还有多久？目前基础如何？是否需要包含前置知识回顾？
2. 用户答：还有两周，以前学过一点网络基础
3. 进入预习模式（Phase 1）
4. 解析大纲：5 个章节，按知识依赖关系确认顺序
5. 定制策略：时间充裕，有基础 — 普通详细度，补充前置知识
6. 搜索补充资料：网络基础概念、各层协议的通俗教程
7. 生成预习材料：每章包含核心概念一览、前置知识回顾、预习要点、课堂准备问题
8. 输出报告 + 询问是否要切换阶段

### ✅ Do This — 冲刺整理 + 用户提供知识点

**用户输入：**
```
帮我整理高数中极限和导数这两章，我极限的概念有点模糊，导数的计算总是出错
```

**期望做法：**
1. 提问确认：时间预算？目前水平？是否需要例题和练习题？
2. 用户答：有 3 天时间，基础一般，需要例题
3. 进入冲刺整理模式（Phase 3）
4. 确认整理范围：用户指定的"极限"和"导数"两个知识点
5. 不擅自添加用户未指定的内容（如积分、微分方程等）
6. 搜索：极限概念的多角度解释、导数计算典型例题
7. 生成材料：知识难度分类 → 每个知识点的精要文件 → 速记卡片
8. 输出整理报告 + 难度分类导航（按基础到困难递进）

### ✅ Do This — 专项攻克 + 用户指定薄弱点

**用户输入：**
```
帮我重点攻克电路分析中的戴维南定理和叠加定理，我老是搞混这两个
```

**期望做法：**
1. 提问确认：具体混淆点？是否有典型题目可以提供？时间预算？
2. 用户答：主要在应用场景上混淆，有 4 天时间
3. 进入专项攻克模式（Phase 4）
4. 确认攻克目标：戴维南定理和叠加定理的辨析
5. 生成对比分析：两个定理的定义、适用场景、使用步骤的逐项对比
6. 搜索：两个定理的经典例题和易混淆点解析
7. 生成材料：概念深度解析（含对比表）+ 强化练习题 + 自检清单
8. 输出攻克方案 + 建议学习路径

### ❌ Not This — 跳过提问直接生成

**用户输入：**
```
帮我整理一下线性代数的资料
```

**错误做法：**
1. 不询问任何参数
2. 直接默认生成一套中等详细度的通用材料
3. 材料既不适合预习也不适合复习，两头不靠

**正确做法：**
1. 主动提问：你是要预习、复习、冲刺整理还是专项攻克？什么时间用？
2. 根据回答选择对应阶段和模板
3. 再追问时间预算和当前水平，调整材料体量和深度

### ❌ Not This — 冲刺模式下擅自添加内容

**用户输入：**
```
帮我整理一下操作系统中的进程管理和内存管理两个知识点，我下周要考试
```

**错误做法：**
1. 不询问用户具体需要哪些知识点
2. 擅自补充了文件管理、设备管理、死锁等用户未指定的内容
3. 自动为用户标注"重点"、"常考"标签
4. 材料中包含了"这个会考"、"那个可以不看"的判断

**正确做法：**

2. 不添加用户未指定的其他知识点
3. 按难度分类整理这两个知识点，标注难点/易混淆点/易忘点
4. 用户问考试相关 → 让用户自己决定需要补充哪些额外知识点

## Notes

- 该 Skill 有四个并联的阶段模式（预习/复习/冲刺整理/专项攻克），每次调用只执行一个阶段
- 如果用户需要多个阶段的材料，建议按"预习 → 复习 → 冲刺整理 → 专项攻克"的顺序分多次调用
- 材料质量取决于用户提供的大纲详细程度和参数明确程度
- 对于没有标准大纲的课程，用户提供知识要点列表即可工作
- 本 Skill 适用于任何学科：理工科、文科、医学、语言等
- 如果用户在前一次会话中已生成过同课程的材料，再次调用时应先检查 `output/` 下是否已有同名目录，避免重复生成
- WebSearch 搜索结果的来源在材料"扩展阅读/"参考来源"中标注，用户可自行前往查看原文
- 如需调整已生成材料的阶段或详细度，只需再次调用本 Skill 并重新选择参数即可
- 本 Skill 的所有输出文件均为纯文本 Markdown 格式，可以直接打印、分享或导入笔记工具
- 质量校验的否决项是硬性门禁，每批材料输出前至少执行一次完整的校验流程
- 学科适应性规则在每次生成材料前根据课程名称自动选择，用户可以在 Phase 0 主动说明学科类型以获取更精准的材料
- 本 Skill 遵循「难度分类，重点用户自定」原则：技能只负责按难度（基础/中等/困难）分类并标注难点/易混淆点/易忘点，不自动指定重点、不判定考试内容、不承诺学习效果
- 冲刺整理和专项攻克模式下，技能**必须**要求用户提供具体的知识点或专题列表才能开始工作，不提供则不生成
- Constraints 中关于禁止考试内容判定的规则是硬性约束，即使时间紧迫也不得违反
