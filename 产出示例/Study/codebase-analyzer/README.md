# Codebase Analyzer

## 简介

全自动、深度化的项目代码分析工具。对指定目录下的所有代码进行全面分析，**粒度精确到函数级别**，生成五份结构化、可交付的 Markdown 报告：项目架构报告、运行原理报告、工作流分析报告、AI 工作流替代方案报告，以及 **Skill Blueprint 设计规格**。每份报告均包含完整的接口契约、调用链追踪、变量级数据流和可操作的 AI 替代方案。

**核心定位**：本工具生成的报告详细到每个项目运行步骤，可作为后续创建 AI 替代 Skill 的完整蓝图。每个 Blueprint 文件包含了创建对应 Skill 所需的全部设计规格（触发词、接口契约、依赖清单、工作流步骤）。

适用于新项目接手、技术复盘、项目归档、架构评审、AI 改造规划等场景。

## 目录结构

```
codebase-analyzer/
├── SKILL.md                        # 技能主文件（核心指令）
├── README.md                       # 本文件（用户文档）
├── references/
│   └── report-templates.md         # 四份报告的详细模板
├── scripts/
│   └── validate-markdown.py        # Markdown 语法校验脚本（纯 Python 标准库，零依赖）
└── templates/                      # 模板文件（预留）
```

## 安装方式

1. 将 `codebase-analyzer/` 目录复制到项目 `.claude/skills/` 下：

   ```bash
   cp -r codebase-analyzer /path/to/your/project/.claude/skills/
   ```

2. 重新启动 Claude Code（或重新加载会话）
3. 使用 `/codebase-analyzer` 或触发关键词激活

> 也可放置在用户级目录 `~/.claude/skills/` 下使其对所有项目可用。

## 使用方式

### 斜杠命令

| 命令 | 说明 |
|------|------|
| `/codebase-analyzer` | 对当前工作目录进行完整项目分析 |
| `/codebase-analyzer <子目录路径>` | 仅分析指定子目录 |

### 自动触发

当用户输入以下关键词时自动激活：
- 分析项目、项目架构、代码库分析
- 项目原理、运行原理、架构分析
- 工作流分析、CI 分析、开发流程
- AI 替代方案、AI 自动化分析、AI 改造
- 项目复盘、项目 review、技术尽调
- codebase analysis、project architecture review

## Workflow 说明

分析过程在隔离子 Agent 中运行，共分为七个阶段：

1. **项目发现与画像** → 扫描目录结构、识别技术栈、配置文件和 Git 元数据，输出项目快照
2. **深度架构分析** → 构建目录全景、追踪模块依赖关系、**函数级调用链追踪**、识别架构模式和设计模式
3. **运行原理分析** → 溯源启动流程、**变量级数据流追踪**、**状态机提取**、错误处理链路、**生命周期钩子分析**
4. **工作流分析** → 分析 CI/CD 管线、测试策略、映射核心业务流程、**决策树提取**、**异常恢复路径分析**
5. **AI 替代方案分析** → 对每个函数评估 6 维度的 AI 替代可行性、**提取接口契约**、**依赖与上下文分析**
6. **Skill Blueprint 生成** → 为每个可替代组件生成完整的 Skill 设计规格（含触发词、接口、工作流、示例）
7. **报告生成** → 生成五份结构化报告 + 汇总索引 + Blueprint 索引，交付前执行 **Markdown 语法校验与修复循环**（脚本校验围栏/表格/Mermaid/链接，自动修复后复检）

## 生成的报告

所有报告输出到项目根目录的 `codebase-analyzer/reports/<项目名>-<时间戳>/` 下：

```
codebase-analyzer/reports/<项目名>-2026-05-19_143000/
├── index.md                           # 分析总览（含核心发现与建议）
├── 01-architecture.md                 # 项目架构报告（含函数级调用链）
├── 02-operation-principles.md         # 运行原理报告（含变量级数据流）
├── 03-workflow.md                     # 工作流分析报告（含决策树）
├── 04-ai-substitution.md              # AI 工作流替代方案报告（含接口契约）
└── blueprints/                        # Skill Blueprint 设计规格
    ├── index.md                       # Blueprint 索引（含实施路线图）
    ├── 01-user-crud-handler.md        # 示例：用户CRUD Skill 设计规格
    └── 02-order-processor.md          # 示例：订单处理 Skill 设计规格
```

每次分析使用独立的时间戳目录，避免覆盖历史结果。

## 技术细节

### 依赖

分析功能无外部依赖（仅使用 Claude Code 内置工具）。语法校验脚本需要 Python ≥ 3.8（纯标准库，零第三方依赖）；Python 不可用时自动降级为 grep + Read 自检，不影响报告生成。

### 使用的工具

| 工具 | 用途 |
|------|------|
| `Glob` | 文件发现与目录树构建 |
| `Read` | 读取源代码文件进行理解 |
| `Grep` | 搜索导入关系、设计模式、API 端点 |
| `Write` | 写入分析报告文件 |
| `Edit` | 修复语法校验发现的问题（精确到行） |
| `Bash` | 目录列表、Git 日志、文件统计、运行语法校验脚本 |
| `WebSearch` | 可选 — 搜索第三方库文档辅助分析 |

### 运行时行为

- 以 `context: fork` + `agent: general-purpose` 模式运行，隔离上下文避免主会话被大量文件内容污染
- 大型项目（>500 文件）自动切换到采样分析模式，在报告中标注
- 生成的文件为纯 Markdown，可在任意编辑器中查看
- 报告中包含 Mermaid 图表，在支持 Mermaid 的 Markdown 渲染器中可展示
- 所有报告在交付前经过 validate-markdown.py 确定性语法校验（代码围栏、表格列、Mermaid 词法、交叉链接），发现问题自动进入修复循环（最多 3 轮），无法消除的 ERROR 会在总结中如实列出

## 报告内容详解

### 1. 项目架构报告 (`01-architecture.md`)
- 完整目录结构全景图（排除生成目录）
- 各目录功能角色分类标注
- 技术栈全景（语言、框架、构建工具、数据库、第三方服务）
- 模块依赖关系图（Mermaid 图表）
- 架构模式识别与定位（MVC、分层、微服务等）
- 关键设计模式实例速查
- 每个观点均附带文件路径和行号引用

### 2. 运行原理报告 (`02-operation-principles.md`)
- 启动初始化序列（配置加载 → 依赖初始化 → 路由注册 → 服务启动）
- 启动时序图（Mermaid sequence 图）
- 核心数据流追踪（2-3 个核心业务路径的完整生命周期）
- 状态管理方式与缓存策略
- 数据持久化层分析（ORM、数据模型、迁移策略）
- 错误处理体系与传播机制

### 3. 工作流分析报告 (`03-workflow.md`)
- CI/CD 管线配置解读（触发条件、阶段、部署策略）
- 测试策略全景（单元测试、集成测试、E2E 测试的框架与覆盖）
- 核心业务流程映射（3-5 个流程，附带工作流图）
- 开发工作流分析（分支策略、Code Review、发布流程）

### 4. AI 替代方案报告 (`04-ai-substitution.md`)
- 每个主要模块的 6 维度 AI 替代可行性评估表
- 三类分级的替代策略（完全 AI 化 / AI 辅助 / 人工主导）
- **函数级粒度分析**：每个函数的签名记录、复杂度评估、接口契约提取
- 每个模块的具体替代实施方案与预期收益
- 实施难度 × 预期收益的 ROI 优先级矩阵
- 三阶段 AI 改造路线图（Quick Win → Strategic → Transformative）

### 5. Skill Blueprint 设计规格 (`blueprints/` 目录)
- 每个可 AI 替代组件的完整 Skill 设计规格
- **基本信息**：推荐 Skill 名称、用途描述、AI 替代等级、实施优先级
- **触发场景**：自然语言触发描述、推荐 description 触发词
- **输入输出契约**：函数接口、数据模型定义、错误码清单
- **依赖清单**：外部服务、内部模块、配置项
- **Skill 工作流设计**：建议的 Workflow 步骤、Constraints
- **所需工具权限**：推荐 allowed-tools 配置
- **使用示例**：✅ Do This / ❌ Not This 对比
- **参考材料**：源文件位置、测试文件、关键代码片段

> 每个 Blueprint 可直接作为 `skill-for-skills` 的输入，自动生成标准 SKILL.md。

## 注意事项

- **只读分析**：本 skill 不会修改任何源代码，仅生成分析报告
- **语法校验（v2.1）**：报告写入后自动校验并修复渲染隐患；3 轮修复后仍存在的问题会在最终总结的「校验遗留问题」中明确列出，不会静默交付
- **时间开销**：完整分析耗时约 2-5 分钟（取决于项目规模），子 Agent 模式下用户可在此期间继续其他工作
- **大型项目**：超过 2000 文件的超大项目会进一步收紧采样策略以控制分析时间
- **AI 替代方案是建议性的**：评估基于代码静态分析，实际可行性需结合业务上下文判断
- **敏感信息**：报告中不会包含代码中的密钥、令牌等敏感信息
- **报告一致性**：多次分析同一项目会生成多个带时间戳的报告目录，便于对比
- **Skill Blueprint 不直接创建 Skill**：Blueprint 是设计规格文档，需配合 `skill-for-skills` 或手动方式基于 Blueprint 创建实际 Skill
- **函数级分析前提**：分析精度依赖于代码的结构化程度。混淆、宏生成或第三方包代码会自动降级到模块级分析

1. **首次分析**：直接在项目根目录执行 `/codebase-analyzer` 获得完整基线报告
2. **增量分析**：关注某个子模块时，用 `/codebase-analyzer <子路径>` 缩小范围获得更深入的分析
3. **版本归档**：每次重大重构或版本发布后重新分析，对比历史报告了解项目演变
4. **AI 改造规划**：利用 AI 替代方案报告确定 Quick Win 项目，快速验证 AI 工作流价值
5. **Skill 创建**：基于 Blueprint 目录中的设计规格，使用 `skill-for-skills` 或手动方式创建对应的替代 Skill。每个 Blueprint 包含完整的 Skill 设计信息，可直接指导 Skill 实现
